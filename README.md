## 1. Introduction

In today's digital world, financial transactions are increasingly moving beyond traditional banking systems and intermediaries.

Cryptocurrency is a form of digital currency that uses cryptographic techniques and blockchain technology to record transactions securely.

Blockchain operates through a decentralized peer-to-peer network in which transaction records are maintained across multiple participating nodes.

Popular cryptocurrencies such as Bitcoin and Ethereum demonstrate how decentralized systems can introduce new approaches to trust, transparency, and security in financial transactions.

This project explores the concepts behind cryptocurrency and blockchain while applying computational thinking principles to understand decentralized transaction systems.

---

## 2. Problem Statement

Traditional financial transactions depend heavily on centralized systems such as banks and payment gateways to verify and process money transfers.

These systems can introduce several challenges:

- High transaction fees due to intermediaries.
- Single points of failure caused by centralized infrastructure.
- Limited transparency in transaction processing.
- Delays in international transactions.
- Risks of fraud and data tampering.
- Limited accessibility for individuals without access to traditional banking services.

The project explores how blockchain-based decentralized transactions can address these challenges through peer-to-peer communication, distributed ledgers, cryptographic security, and consensus mechanisms.

## 4. Computational Thinking Principles

This project applies four major computational thinking concepts.

### 4.1 Decomposition

Breaking the decentralized transaction system into smaller components:

- User accounts.
- Transaction creation.
- Transaction verification.
- Cryptographic hashing.
- Block formation.
- Distributed ledger maintenance.

### 4.2 Pattern Recognition

Identifying recurring structures and patterns in blockchain transactions:

- Repeated transaction formats.
- Block structures.
- Hash relationships.
- Transaction validation procedures.

### 4.3 Abstraction

Focusing on the essential components of a blockchain system while ignoring unnecessary implementation details.

For example, representing a transaction using sender, receiver, amount, and transaction identifier.

### 4.4 Algorithm Design

Developing logical steps for:

- Creating transactions.
- Verifying transaction validity.
- Generating cryptographic hashes.
- Linking blocks.
- Maintaining transaction records.

## 5. Existing System

Most conventional digital transactions use centralized platforms.

Examples include:

- Banks and payment gateways.
- Visa and Mastercard.
- PayPal.
- UPI-based payment systems.
- Centralized wallets and exchanges.

A central organization verifies, records, and approves transactions.

### Limitations

1. Single point of failure.
2. Transaction processing fees.
3. Potential delays in cross-border payments.
4. Limited visibility into internal transaction processing.
5. Dependence on centralized authorities.
6. Accessibility limitations.

---

## 6. Proposed System

The proposed approach explores blockchain-based decentralized transactions.

Instead of relying entirely on a central authority, participating network nodes maintain a distributed ledger.

### Main Components

**Decentralized Ledger**

Transaction records are maintained across participating network nodes.

**Peer-to-Peer Transactions**

Users can transfer digital assets directly through a blockchain network.

**Consensus Mechanism**

Network participants validate transactions using consensus mechanisms such as:

- Proof of Work (PoW).
- Proof of Stake (PoS).

**Cryptographic Security**

Cryptographic hashing helps protect transaction records and link blocks together.

**Transparency**

Blockchain records can be independently verified through the distributed ledger.
